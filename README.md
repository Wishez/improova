# Импрува

Трекер и планировщик годового челленджа художника: программа «разделы → темы → топики» с прогрессом, план на неделю, таймер сессий с логами, заметки с фото, статистика и прогноз.

Данные хранятся только в браузере (IndexedDB). Резервная копия — экспорт JSON в «Настройках».

## Стек

Angular 22 (standalone, zoneless, signals) · Taiga UI 5 · Tailwind CSS 4 · IndexedDB (`idb`) · Vitest.

## Запуск

Нужен Node.js ≥ 22.22.3.

```bash
npm ci
npm start            # http://localhost:4200
npm test -- --watch=false
npm run build:pages  # сборка под GitHub Pages (/improova/)
```

## Деплой

Push в `main` → GitHub Actions (`.github/workflows/deploy.yml`) прогоняет тесты, собирает и публикует на GitHub Pages.
Однократно: Settings → Pages → Source: **GitHub Actions**.

Заметки к выпускам — [CHANGELOG.md](CHANGELOG.md): что нового и что сделать до обновления.

### Откат

1. До выпуска релиза, который меняет схему данных (`SCHEMA_VERSION`), — полный экспорт JSON в каждом браузере: «Настройки» → «Скачать копию (JSON)».
2. Перед откатом, если новая версия открывается: записать число сессий и итог «Статистики» за «Весь челлендж» и сделать полный экспорт JSON в новой версии. Числа нужны для проверки после отката (п. 4), файл — для пунктов 6 и 7.
3. Код. Релиз попадает в `main` слиянием ветки, поэтому откат — `git revert -m 1 <merge-коммит релиза>` в ветке от `main` и pull request в `main`; без `-m 1` revert merge-коммита не выполняется. Обычный коммит — `git revert <sha>`. После слияния Actions прогоняет тесты и публикует прошлую версию.
4. Проверка: run «Deploy to GitHub Pages» для коммита отката зелёный. В браузере — закрыть все вкладки Импрувы и открыть заново с обновлением без кеша (Ctrl+Shift+R): открытая вкладка работает на коде новой версии до перезагрузки, её записи прошлая версия тоже прочитает. Число сессий и итог «Статистики» — те же, что записаны в п. 2.
5. Данные. Прошлая версия открывает базу новой схемы как есть, пока релиз не менял версию базы IndexedDB (`DB_VERSION` в `storage/indexeddb.adapter.ts`): схема только добавляет поля, а запись сохраняет незнакомые поля (ADR-007, «Откат»). Копию до обновления не импортировать: «Заменить» удалит всё, что записано после обновления, «Объединить» вернёт логи, удалённые в новой версии.
6. Файл экспорта новой версии прошлая не импортирует («ошибка в schemaVersion»), данные при этом не меняются. Экспорт, сделанный после отката, новая версия импортирует. Запасной путь 1.6 → 1.5, если данные есть только в файле экспорта 1.6 (перенос в другой браузер): в файле заменить `"schemaVersion":5` на `"schemaVersion":4` — 1.5 импортирует его со всеми логами и сведениями о шагах (проверено на копии, вкладка «Релиз 1.6»).
7. Если после отката приложение показывает «Не удалось открыть данные»: «Восстановить из файла копии» — сначала экспорт из п. 2 с правкой номера схемы по п. 6, а если его нет — копия до обновления из п. 1; тогда сессии, записанные после обновления, пропадут.
8. Повторный выпуск — `git revert` коммита отката: повторное слияние той же ветки изменений не вернёт.

Граница плана отката 1.6: срока по времени нет (Q-041), план действует, пока слияние 1.6 — последнее в `main`. После следующего выпуска 1.6 отдельно не откатывается: только исправление вперёд или откат того выпуска по его плану (Q-047).

## Структура

```
src/app/
  types/       контракты сущностей, один на файл
  utils/       даты с границей дня, форматирование, id, файлы
  domain/      чистая логика: программа, прогресс, оценки, повторения, планировщик, статистика, подсказки
  storage/     IStorageAdapter, IndexedDB и in-memory реализации, проверка и миграция снимков
  seed/        стартовая программа
  services/    состояние (signals) и сценарии: программа, таймер, логи, план, заметки, бэкап
  pipes/       форматирование в шаблонах
  components/  общие компоненты и диалоги
  pages/       экраны (lazy): onboarding, today, program, plan, notes, stats, settings
```

Решения — `docs/adr/`. Правила для агентов — `AGENTS.md`.
