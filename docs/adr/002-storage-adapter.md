# ADR-002. Адаптер хранилища и запись «память → диск»

Статус: принято · 2026-09

## Контекст

Интерфейс должен реагировать мгновенно, запись не должна терять данные при сбое IndexedDB и при быстрой серии изменений.

## Варианты

1. Асинхронные вызовы хранилища из каждого сервиса.
2. Состояние в signals (`DataStore`), очередь изменённых сущностей, последовательная запись через `IStorageAdapter`.

## Решение

Вариант 2. Изменение сразу видно в UI, запись идёт одной очередью: следующий сброс начинается только после предыдущего, поэтому старая версия сущности не перезапишет новую. При ошибке — повтор через 2/4/8 с и тост; при уходе со страницы с незаписанными данными — предупреждение.

Реализации: `IndexedDbAdapter` (прод), `MemoryAdapter` (тесты и браузеры без IndexedDB).

## Цена отказа от 1

Одна точка записи (`DataStore`) — сервисы не должны писать в адаптер напрямую.
