# ADR-004. Ориентиры в топике и вычисляемый календарь

Статус: принято · 2026-09 · релиз 1.2 (FR-36…FR-42)

## Контекст

Курс годового челленджа должен открываться в каждой сессии без поиска, а весь период — быть виден в календаре. Данные остаются в браузере (ADR-001).

## Решения

1. **Ориентир — поле `guide` у топика**, а не отдельная коллекция. Один топик — один ориентир, экспорт и импорт программы переносят его вместе с топиком. Отказ от коллекции: нельзя переиспользовать ориентир между топиками; серии «· N/M» хранят свой ориентир у каждого топика.
2. **Маршрут мастеров — коллекция `routeBlocks`** с номерами недель. Повторяющиеся топики маршрута помечены `routeRole` и берут художника недели при показе. Отказ от генерации 26 отдельных топиков: история логов остаётся у одного топика, а замена художника не трогает прогресс.
3. **Календарь вычисляется**, как и план недели (ADR-003): прошлое — логи против плана дня, горизонт 7 дней — планировщик, дальше — прогноз минут по разделам с весами квартала. Хранится только план дня, зафиксированный в сам день (`meta.dayPlans`), чтобы новые настройки не переписывали прошлое.
4. **Схема v2 только добавляет поля.** Нормализация при загрузке и импорте ставит значения по умолчанию; квартальные веса у данных v1 выключены. Ориентиры курса в начатый челлендж добавляются явным действием с предпросмотром и заполняют только пустые поля.

## Цена

Прогнозные дни показывают разделы, а не топики: топики назначаются только на 7 дней вперёд. Действие «Добавить ориентиры курса» сопоставляет топики по названию «раздел / тема / топик» — переименованные топики остаются без ориентира и видны в списке «не найдено».

## Откат

Экспорт JSON из 1.2 импортируется в 1.1 только частично (1.1 отклоняет схему 2). Откат релиза — `git revert` и импорт копии, скачанной до обновления.
